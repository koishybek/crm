# Home Max Service — заявки, заказы и мастера для сервисной компании

По ТЗ `../CRM_AI_Service_Platform_TZ.docx`.
Этап 1 (MVP): заявки → заказы → лента исполнителей → выполнение → оплата → аналитика.
Этап 2: Telegram-бот (команда и клиенты), AI-разбор звонков и обращений, телефония (АТС), раздел «Звонки».
Этап 3: единые «Сообщения» (Telegram, WhatsApp, OLX, сайт, API), навыки, журнал действий, отзывы и рейтинг, деньги (оплаты, сторно, возвраты, выплаты мастерам), регламенты и эскалации, кабинет мастера как приложение (PWA), бэкапы, «Состояние системы», защита данных — см. раздел «Этап 3».

- **Фронт:** React 19 + Vite + Tailwind 4, статикой на Cloudflare Workers (`wrangler.jsonc`).
- **Бэкенд:** Convex (база, функции, файлы, кроны, вебхук Telegram), проект `servicepro` в команде `koishybek-o`.
- **Вход:** Convex Auth, логин (email или телефон) + пароль. Регистрации нет — аккаунты создаёт владелец.
- **AI:** разбор обращений — OpenAI-совместимый LLM (`LLM_*`, сейчас TokenLayer `gpt-5.6-luna`; шлюз принимает только роль `user`), запасной — `../ai-service`: Worker на Cloudflare Workers AI (Whisper large v3 turbo + Llama 3.3 70B), `https://servicepro-ai.koishybek-o.workers.dev`; расшифровка — Whisper там же.
- **Название** — константа `APP_NAME` в `src/data/catalog.ts`; профиль бота — `node scripts/setup-telegram.mjs --profile`.
- **Бот:** @oolx_crm_bot («Home Max Service»), вебхук → `https://fleet-weasel-433.convex.site/telegram`.

## Запуск для разработки

```bash
npm install
npm run convex      # выкатывает функции на dev-деплоймент (и следит за изменениями без флага --once)
npm run dev         # http://localhost:5190
npm run typecheck   # фронт + convex
npm test            # серверные тесты (convex-test)
```

Демо-данные (90 дней истории от «сегодня»):

```bash
CONVEX_DEPLOY_KEY='dev:…|…' DEMO_PASSWORD='не-короче-10-символов' npm run seed -- --wipe
# то же без npm: npx tsx scripts/seed-convex.ts --wipe
```

- Функции `seed:*` внутренние: клиенты их не видят, скрипт зовёт их с правами администратора деплоймента — **ключом деплоя** (панель Convex → деплоймент → Settings → URL & Deploy Key → Generate). Общего секрета (`SEED_SECRET`) больше нет. Ключ — как пароль администратора: в репозиторий, чаты и CI-логи не класть.
- На деплойменте должен стоять `ALLOW_SEED=1` (`npx convex env set ALLOW_SEED 1`); без него скрипт ничего не удалит и не зальёт.
- Адрес деплоймента — `CONVEX_URL` или `VITE_CONVEX_URL` из `.env.local`, иначе берётся из ключа. Ключ от другого деплоймента, чем адрес, — скрипт останавливается до любых изменений.

Заливка добавляет звонки: к заявкам «с телефона», пропущенные сегодня и две записи разговоров (`scripts/demo-calls/*.mp3`), которые проходят настоящий AI — через минуту из них появляются заявки. Привязки Telegram при перезаливке сохраняются, ключ АТС не трогается.
Пароль демо-аккаунтов задаётся при заливке (`DEMO_PASSWORD=…`) и в репозиторий не попадает; менять его при входе демо-аккаунтам не нужно. Кнопки быстрого входа видны, только если сборка сделана с `VITE_DEMO_PASSWORD` — пароль при этом оказывается в публичном JS, поэтому на стенде с реальными каналами (бот, АТС) так не собирать.

## Проверки в браузере

Нужен Chrome и база с демо-данными (лучше локальная — облачные лимиты Convex не тратятся: `npx convex deployment create <команда>:<проект>:local --select` в отдельной копии, `npx convex dev`, затем `npm run seed`).

```bash
E2E_PASSWORD='пароль демо' BASE=http://localhost:5190 npm run e2e:flow    # заявка → заказ → мастер → оплата → выплата
E2E_PASSWORD='пароль демо' BASE=http://localhost:5190 npm run e2e:audit   # все экраны × роли × размеры экрана
```

`e2e:audit` ищет ошибки консоли, горизонтальную прокрутку, содержимое, которое не влезает и не прокручивается, обрезанный текст и мелкие кнопки на телефоне (`ONLY=owner-phone` — один набор); скриншоты — `e2e/out/`. Оба скрипта завершаются с ошибкой, если что-то нашли.

## Почта и внешние копии (без Resend и R2)

- **Почта через обычный ящик:** `node scripts/setup-email.mjs [--prod] <host> <port> <логин>` — пароль приложения спросит скрипт и в консоль не выведет (`EMAIL_SMTP_HOST/PORT/USER/PASS`, отправитель — `EMAIL_FROM` или сам ящик). - **Внешние копии в Cloudflare KV:** Worker `backup-worker/` (`homemax-backup`, KV `BACKUPS` уже создан и вписан в `wrangler.jsonc`). Выкладка — `cd backup-worker && npx wrangler deploy`, секрет — `npx wrangler secret put BACKUP_SECRET`; в Convex — `BACKUP_WORKER_URL=https://homemax-backup.koishybek-o.workers.dev` и тот же `BACKUP_WORKER_SECRET`. Подключено к боевой базе; демо — только копии в Convex. Файл больше 25 МБ в KV не помещается — пропускается с пометкой.

## Боевой запуск у заказчика

1. Отдельный деплоймент, где демо-данные никогда не заливались (или очистка: временно `ALLOW_SEED=1`, `CONVEX_DEPLOY_KEY='prod:…' npm run seed -- --wipe`, прервать после «Очищаю базу…», затем `npx convex env remove ALLOW_SEED --prod`).
2. Создать владельца — только из CLI, только в базе без владельцев, пароль от 12 символов: `npx convex run --prod seed:bootstrapOwner '{"name":"…","login":"…","password":"…"}'`. Второй вызов отказывает («Владелец уже есть»).
3. Задать `INTEGRATIONS_KEY`; убедиться, что `ALLOW_SEED` нет; собрать фронт **без** `VITE_DEMO_PASSWORD`.
4. Владелец: «Настройки» → операторы; импорт исполнителей и клиентов из Excel; бот Telegram. Пароль, выданный при создании или сбросе, — временный: при первом входе человек задаёт свой (экран «Смените пароль», владельцу — от 12 символов, остальным — от 10). Сменить пароль самому — меню профиля → «Сменить пароль».
5. Телефония: «Настройки → Телефония» → «Создать ключ подключения»; адрес и ключ — в настройки вебхука облачной АТС (ключ — в заголовке `X-PBX-Secret`).
6. Свой домен для фронта и AI-сервиса: адреса `*.workers.dev` из Казахстана открываются не у всех провайдеров.

## Восстановление из резервной копии

Файл копии — «Настройки → Резервные копии → Скачать» или из внешнего хранилища (`backups/homemax-backup-….json`).

```bash
CONVEX_DEPLOY_KEY='prod:…|…' npx tsx scripts/restore.ts homemax-backup-2026-10-13-0200.json --dry-run   # план, ничего не меняет
npx convex env set --prod ALLOW_SEED 1
CONVEX_DEPLOY_KEY='prod:…|…' RESTORE_OWNER_PASSWORD='не-короче-12-символов'   npx tsx scripts/restore.ts homemax-backup-….json --yes --owner-login=owner@firma.kz [--wipe]
npx convex env remove --prod ALLOW_SEED
```

- Запись — только с `--yes` и `ALLOW_SEED=1`; если в базе уже есть данные — отказ без `--wipe` (стирает данные, входы и служебные таблицы; настройки, подключения и файлы хранилища остаются).
- Документы получают новые id, все ссылки переписываются. Ссылки на файлы, которых нет в хранилище деплоймента, убираются (сами файлы — во внешнем хранилище `files/<storageId>`, если владелец включил их копирование).
- Паролей в копии нет: `--owner-login` даёт владельцу временный пароль (`RESTORE_OWNER_PASSWORD`), остальным пароли выдаёт владелец. Ключи API, вебхуки и OLX — заново (их секретов в копии нет).

## Этап 2: Telegram, AI, телефония

- **Бот для команды** (`convex/telegram.ts`, `convex/worker.ts`): сотрудник или мастер жмёт «Подключить Telegram» в меню профиля. Мастерам новые заказы приходят карточкой с кнопкой «Взять»; дальше заказ ведётся кнопками (подтвердить → начать → выполнено) — те же мутации, что в кабинете. `/orders`, `/feed`. В 9:00 по Алматы — сводка (`convex/digest.ts`): владельцу с деньгами, мастерам — заказы на сегодня.
- **Бот для клиентов** (`convex/bot.ts`): клиент пишет текстом, голосом (расшифровывает AI) или присылает фото → кнопка «Отправить мой номер» → заявка в CRM с источником Telegram и AI-разбором. Следующие сообщения в течение 3 дней дописываются к этой заявке. Принимается только свой контакт (кнопкой, `user_id` = отправитель); антиспам: 20 сообщений в минуту с чата (о лимите бот говорит раз в 10 минут), голосовые — до 2 минут и не больше 10 в час на расшифровку, описание — до 3000 символов, новые заявки — 3 в сутки с чата. Повтор доставки вебхука (тот же `update_id`) не обрабатывается; ссылка привязки Telegram из кабинета живёт 30 минут и срабатывает один раз; кнопки действуют только в личном чате нажавшего.
- **AI** (`convex/ai.ts`): расшифровка записи → разбор в черновик заявки (услуга только из справочника, город, адрес, когда, бюджет, срочность, имя, вопросы оператору). Фантомные фразы Whisper на тишине вырезаются. Если услуга понятна, звонок сам становится заявкой. В форме новой заявки — «Заполнить с AI»: вставить переписку или загрузить запись.
- **Телефония** (`convex/calls.ts`, `convex/http.ts`): `POST /pbx/events` с ключом в заголовке `X-PBX-Secret` (если есть и заголовок, и `?secret=`, проверяется заголовок). `?secret=` в адресе принимается для АТС, которые не умеют заголовки, но это менее безопасно: адрес с ключом оседает в журналах АТС и прокси. Тело — до 64 КБ; время события (`at`) дальше суток от «сейчас» заменяется текущим; отказы по ключу — в «Состоянии системы» и в журнале (не чаще раза в 10 минут). Пример:

  ```json
  {"event": "ringing",  "callId": "abc-123", "direction": "in", "from": "+77011234567", "to": "+77273450000"}
  {"event": "answered", "callId": "abc-123", "operator": "madina@homemax.kz"}
  {"event": "ended",    "callId": "abc-123", "duration": 184, "recordingUrl": "https://pbx.example/rec/abc-123.mp3"}
  ```

  Понимаются и другие названия полей (`caller`, `callee`, `call_id`, `billsec`, `record_url`, …) и form-data. Входящий звонок всплывает карточкой у владельца и операторов (клиент, заказы, «Новая заявка»), пропущенный — уведомление. Запись по ссылке CRM скачивает в своё хранилище и отдаёт AI.
- Диагностика AI с сервера: `npx convex run aiCheck:run '{"text":"…"}'` (или `storageId` записи).

## Этап 3

- **Сообщения** (`convex/inbox.ts`, `convex/channels/*`, `lib/outbound.ts`): один список переписок Telegram, WhatsApp (Cloud API, окно 24 ч), OLX (Partner API, опрос раз в минуту), формы сайта `/zayavka` (`POST /public/lead`, антиспам) и REST API (`/api/v1/leads`, ключи в «Настройках»). Из переписки — заявка в один клик с AI-черновиком.
- **Клиенту в его канал** (`convex/clientNotify.ts`): «мастер приедет …», «работа выполнена» со ссылкой на оценку (в Telegram — кнопки ⭐), «заказ отменён». Отзывы — `/otzyv/:token`, рейтинг мастера байесовский (`convex/reviews.ts`).
- **Навыки и подбор** — одно правило `fitsOrder` (`src/data/logic.ts`): город, направление, навыки, приём заказов, лимит заказов в работе. Автораспределение «AI-подбор» и эскалации по срокам — крон `operations` (`convex/autoAssign.ts`, `convex/escalations.ts`), пороги — «Настройки → Сроки реакции».
- **Деньги** (`convex/finance.ts`, `convex/payouts.ts`, `lib/money.ts`): оплаты с датой и сторно, возвраты записями, статус идёт за деньгами («Ожидает оплаты» ↔ «Оплачен»), сумма мастера фиксируется при взятии, реестр «Выплаты мастерам», аналитика по датам денег. Деньги — по правам сотрудника: каждый заказ уходит наружу через `moneyFor` (`lib/dto.ts`).
- **Мастер видит только своё**: без цен компании и внутренней переписки, канал «С мастером», файлы — с отметкой «Показать мастеру», контакты клиента — после подтверждения. Все файлы и записи — по подписанным ссылкам (`convex/files.ts`), загрузки проверяются по типу и размеру.
- **Журнал действий** (`convex/audit.ts`, раздел владельца), **архив заказов**, **долги клиентов**, **экспорт CSV на сервере** (`convex/exports.ts`, защита от формул, ссылка на сутки).
- **Надёжность**: ночная резервная копия (`convex/backup.ts`, 14 последних, с описью файлов) и её копия во внешнем S3 (`convex/offsite.ts`, подпись SigV4 — `lib/sigv4.ts`, 30 последних; файлы — по настройке владельца), восстановление (`scripts/restore.ts`), оповещения владельцу о сбоях и «давно не работало» (`convex/alerts.ts`: Telegram, колокольчик, email — не чаще раза в час, «восстановилось» одним сообщением), ошибки интерфейса в «Состоянии системы» (`convex/clientErrors.ts`), срок хранения записей звонков (`convex/retention.ts`, по умолчанию 365 дней), уведомления на телефон — web push без зависимостей (`convex/push.ts`, `lib/webpush.ts`: RFC 8291/8292) и офлайн-экран (`public/sw.js`), «Состояние системы» по подсистемам, удаление данных клиента по его просьбе (`clients.anonymize`), токены OLX в базе зашифрованы, временные пароли с обязательной сменой, отключённый сотрудник теряет доступ сразу.
- **Адаптеры интеграций** (ТЗ п.19.1, 19.7–19.9; «Настройки → Провайдер АТС / Онлайн-оплата / Документы и 1С»; ключи провайдеров — зашифрованы `INTEGRATIONS_KEY`):
  - АТС `convex/pbx.ts`, `lib/pbx/*` — Binotel, Zadarma (подпись `Signature`), OnlinePBX: `POST /pbx/<провайдер>?key=<ключ АТС>` → `calls._ingest`, запись — по API провайдера, «Позвонить через АТС» (`calls.dial`, внутренний номер сотрудника; иначе `tel:`).
  - Оплата `convex/payments.ts`, `lib/pay/*` — Freedom Pay и CloudPayments: «Выставить счёт на оплату» в заказе → ссылка → уведомление `POST /pay/<провайдер>` (подпись) → оплата от «Система» через `lib/money.recordPayment`; Kaspi — ссылка магазина, оплату отмечают вручную.
  - Документы `convex/documents.ts` — счёт и акт со снимком, печать `/docs/<invoice|act>/<заказ>`, ссылка клиенту `/d/<токен>` (30 дней, нужен `APP_URL`); выгрузки для 1С — `convex/accounting.ts` (реестр денег CSV, CommerceML 2 XML).
- **Кабинет мастера** (`src/screens/worker/*`, `convex/executorApp.ts`): лента в стиле Яндекс Про, «Мои заказы», «Доход» с выплатами, профиль с приёмом заказов «до …»; ставится на телефон (PWA, `public/manifest.webmanifest`).

## SaaS: несколько компаний

Платформа обслуживает несколько компаний (ТЗ §2.5, §23.7, §24.2–§24.5); данные каждой видит только она сама.

- **Изоляция** (`convex/lib/tenantDb.ts`, `convex/lib/functions.ts`): все модули берут `query/mutation/action/…` из `lib/functions`, где `ctx.db` — обёртка с компанией вызова: из вошедшего пользователя (`users.tenantId`; нет поля — компания по умолчанию `t-komfort`), явного `tenantId` или документа из аргументов внутренней функции. Списки читаются по индексам `t_<имя>` (компания первым полем) или с фильтром по компании; чужой документ по id — `null`, запись в чужой — ошибка; компания передаётся по цепочке планировщика и `runQuery/runMutation`. Таблицы входа, реестр `tenants` и лимиты — общие; `unscopedDb` — только миграция, платформа, поиск по общим ключам (логин, ключ API, ключ АТС, токены ссылок).
- **Входы без пользователя**: форма `/zayavka?c=<компания>` и `POST /public/lead?c=…` (без `c` — первая компания), REST API — компания ключа, АТС — компания ключа `X-PBX-Secret`, уведомления оплаты — `/pay/<провайдер>?c=…` (без `c` — компания по умолчанию; подпись проверяется ключами этой компании), ссылки отзыва и документа — компания токена, подписанные ссылки на файлы — `&c=…` (ключ подписи компании). Бот Telegram и номер WhatsApp из окружения — компании по умолчанию (сотрудники любых компаний получают уведомления через этот же бот). Кроны обходят компании (`perTenant`): одна компания — сразу, несколько — отдельным запуском на каждую. Резервные копии — у каждой компании свои; во внешнем хранилище — папка `t/<компания>/` (у компании по умолчанию — корень, как раньше).
- **Тарифы и модули** (`src/data/plans.ts`, `convex/lib/tenant.ts`): «Бесплатный» (3 сотрудника, 5 исполнителей, 50 заказов в месяц, без модулей), «Стандарт» (15/50/1000; телефония, WhatsApp, OLX, онлайн-оплата, документы), «Про» (без лимитов, все модули). Модули проверяет сервер (`hasModule`) на входе функций: AI, телефония, WhatsApp, OLX, онлайн-оплата, документы, расширенная аналитика (кампании), API и вебхуки; в интерфейсе — замок «Доступно на тарифе …». Тариф, модули, статус и комиссию меняет администратор платформы на экране «Платформа» (`PLATFORM_ADMINS`).
- **Комиссия платформы** (§24.2): процент или сумма с выполненного заказа — снимок `orders.platformFee` при выполнении; в «Аналитике» — строка «Комиссия платформы», маржа = цена клиента − выплата мастеру − комиссия (общие формулы `src/data/logic.ts`, `src/data/analytics.ts`). У демо-компании комиссии нет.
- **Компании и подписка вручную** (`convex/platform.ts`, `convex/billing.ts`, правила — `src/data/billing.ts`): на «Платформе» — «Создать компанию» (название, адрес, город, тариф, владелец, «оплачено до»; тот же шаг, что регистрация; временный пароль владельца показывается один раз, при входе он задаёт свой). Оплату подписки платформа принимает сама (Kaspi, перевод, наличные, карта) и вносит «Принять оплату»: N месяцев или дата — продление с max(«оплачено до», сегодня); отмена последней оплаты — в течение суток. Список: срок (оплачено / заканчивается ≤ 7 дней / просрочено N дней), последняя оплата, нагрузка против лимитов тарифа, вкладки «Просроченные»/«Заканчиваются»/«Приостановленные», выгрузка оплат в CSV. «Настройки платформы»: льготные дни (по умолчанию 5), «Как оплатить», цены тарифов в месяц (подсказка суммы). Крон раз в день (08:30 Алматы): за 7 и за 1 день — напоминание владельцу (колокольчик, Telegram, email «Подписка») и администраторам платформы; после льготных дней — приостановка (данные остаются, экран «Доступ отключён» с текстом «Как оплатить»), оплата возобновляет сама. Без «оплачено до» — бессрочно (демо-компания); компанию администратора платформы и приостановленную вручную крон и оплата не трогают. Владелец видит подписку в карточке «Компания» и плашку на «Главной» за 7 дней.
- **Регистрация** (`/register`, `convex/tenants.ts`): при `SAAS_SIGNUP=1` — компания, владелец (пароль от 12 символов) и справочник по умолчанию, тариф «Бесплатный»; ловушка для ботов, время заполнения, лимиты. Владелец сразу входит и видит «С чего начать» на «Главной»; карточка «Компания» в «Настройках» — название, адрес компании, тариф, лимиты, модули.

**Перевод боевой базы (один раз, сразу после выкладки функций):**

```bash
npm run deploy:convex                                        # 1. схема (новые поля и индексы) и функции
npx convex run --prod tenants:migrate '{}'                   # 2. строка «Home Max Service» (тариф «Про», все модули) и tenantId во всех документах
npx convex run --prod tenants:migrationStatus '{}'           # 3. migratedAt заполнен — перенос закончен (идёт шагами по 200 документов, ~10 тыс. — около минуты)
npx convex env set --prod PLATFORM_ADMINS owner@homemax.kz   # 4. по желанию: администратор платформы
```

До шага 2 всё работает как раньше (документы без `tenantId` считаются документами компании по умолчанию); повторный запуск миграции безопасен. `SAAS_SIGNUP=1` включать после миграции. Демо: `npm run seed -- --wipe` сам создаёт строку демо-компании с тарифом «Про».

## Устройство

- `convex/schema.ts` — таблицы; даты — ISO-строки UTC. На заявках и заказах копии имени/телефона клиента, на клиенте — счётчики заказов (`refreshClient`).
- Роли: владелец, оператор, руководитель направления (`categories` на пользователе — видит только эти направления, без клиентской базы), исполнитель.
- Права поверх роли (ТЗ п.5.12) — `src/data/permissions.ts` (`can`, умолчания ролей), сервер — `requirePerm` в `lib/access.ts`, владелец меняет их в «Настройки → Доступ → Роль и права» (`convex/permissions.ts`, журнал). Оператор по умолчанию видит цену и оплаты, но не выплаты мастерам и маржу; руководитель — без денег.
- Телефоны клиентов: Казахстан и Россия — «7XXXXXXXXXX», другие страны — E.164 без «+» (`src/data/phone.ts`, маска ввода — KZ по умолчанию, «+код» — другая страна).
- Справочник направлений и услуг — таблицы `categories`/`services` (`convex/catalog.ts`), правит владелец в «Настройках»; пока база пуста — значения по умолчанию из `src/data/catalog.ts`. Фронт подменяет справочник после входа (`setCatalog`).
- Экспорт в Excel (CSV) — «Заказы», «Клиенты», «Аналитика».
- `convex/lib/access.ts` — роли (`requireRole`, `scopeOf`/`assertScope` для руководителя); `convex/lib/dto.ts` — наружу только DTO. Исполнитель получает `WorkerOrder`: без цены клиента и маржи, адрес и телефон — после подтверждения.
- «Взять заказ» (`worker.takeFor`) — мутация Convex = сериализуемая транзакция: из двух одновременных побеждает одна.
- Уведомления: `lib/domain.notify` пишет в колокольчик и через планировщик шлёт в Telegram (после коммита). Напоминания о сроке — `crons.ts` раз в 15 минут.
- Показатели «Главной» и «Аналитики» — предрасчёт (`convex/stats.ts`, правила — `src/data/dailyStats.ts`): правка заказа (`lib/domain.log`) или заявки ставит её в очередь, раз в минуту крон складывает факты по дням Алматы × направление × источник × город (с разбивкой по мастерам и операторам) и по месяцам; экраны читают итоги за период — O(дней), формулы денег общие (`src/data/analytics.ts`, паритет — `src/data/dailyStats.test.ts`). Первый запуск и кнопка владельца в «Аналитике» — полный пересчёт. Загрузка мастера для подбора — счётчик `executors.activeCount`.
